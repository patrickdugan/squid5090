# RTX 5080 (16 GiB) port

The RTX 5080 and 5080 Laptop GPU are the same Blackwell `sm_120` family as the 5090, so every
kernel builds unchanged for `sm_120a`. What differs is memory and the driver line:

| | RTX 5090 | RTX 5080 Laptop |
|---|---|---|
| VRAM | 32 GiB | 16 GiB (15.54 GiB free on an idle Windows desktop) |
| SMs / L2 | 170 / 96 MiB | 60 / 64 MiB |
| Driver / CUDA | 590.x / CUDA 13.1 | 577.x / CUDA 12.9 max |
| OS | Linux | Windows 11 + WSL2 (Ubuntu 24.04) |

## What changed

1. **CUDA 12.8+ builds.** `cuda/cuda_abi.cu` maps the edge-data graph-capture calls used by the
   adaptive `{2,4,8}` switch graph to their CUDA 12 names (`cudaStreamGetCaptureInfo_v3`,
   `cudaGraphAddNode_v2`, `cudaStreamUpdateCaptureDependencies_v2`). CUDA 13 builds are unchanged.
   `cudaGraphCondTypeSwitch` and PDL are available from CUDA 12.8.
2. **Embed table on the host by default below 24 GiB.** The BF16 embed table (0.86 GiB) moves to
   zero-copy pinned host RAM, as upstream already does above 512K context. `--embed-device` keeps it
   on the GPU.
3. **Context and KV fitted to free VRAM.** After the weights load, the CLI computes the runtime
   arena for the requested `--ctx` and `--kv` (`engine.runtime_vram_bytes_for`). If it does not fit,
   auto KV switches `fp8 -> q4`, then context shrinks to the largest multiple of 1024 that fits
   (floor 4096). An explicit `--ctx` or `--kv` that does not fit exits with the numbers instead.
4. **No silent paging.** Under WDDM (Windows and WSL2) a `cudaMalloc` past physical VRAM succeeds
   and pages to system RAM. The weight loader checks free VRAM first and exits if weights + load
   staging + reserve do not fit. Free VRAM comes from NVML (`libnvidia-ml.so.1`, the figure
   nvidia-smi shows), falling back to `cudaMemGetInfo`. Under WSL2 `cudaMemGetInfo` returns the WDDM
   residency budget: 14.61 GiB on an idle 5080 Laptop, where NVML reports 15.36 GiB and a 15.0 GiB
   allocation reads at 853 GB/s (full speed, no paging). `SQUID_VRAM_RESERVE_MIB` (default 384) is
   kept free for cuBLAS workspaces and graph instantiation.
5. **`-Dprefill-batch=512|1024|2048`.** Every prefill scratch buffer scales with the chunk size
   (2048 is upstream's default and costs ~0.7 GiB). 1024 frees 0.34 GiB for KV.

## Budget

`python tools/vram_budget.py` mirrors `compute_runtime_vram_bytes`; at nvfp4 / q4 / 8K it gives
15.60 GiB with the embed table on the GPU, against 15.59 GiB measured on the 5090. On an idle 5080
Laptop under WSL2 the process sees 15.36 GiB free after creating its context; with 13.70 GiB of
weights (host embed) and the 384 MiB reserve that leaves 1.29 GiB for the runtime arena:

| `-Dprefill-batch` | KV | runtime at 8K | largest ctx that fits |
|---:|---|---:|---:|
| 2048 | fp8 | 1.09 GiB | 18,432 |
| 2048 | q4 | 1.03 GiB | 35,840 |
| 1024 | q4 | 0.69 GiB | 72,704 |
| 512 | q4 | 0.52 GiB | 92,160 |

The model needs the card to itself: another process holding more than ~0.4 GiB of VRAM leaves too
little for the weights (13.70 GiB + 0.86 GiB load staging + reserve).

## Checks

`tests/switch_graph_smoke.cu` builds the adaptive `{2,4,8}` conditional-switch graph through the
same `squid_adaptive_graph_*` ABI the engine uses and drives each branch (build line in the file).
On the RTX 5080 Laptop (WSL2, CUDA 12.8 runtime, driver 577.05) it selects widths 2/4/8 and runs
bodies 0/1/2, and prints NVML free VRAM next to `cudaMemGetInfo`.

## Build and run on Windows (WSL2)

Inside WSL2 Ubuntu 24.04 with the Windows NVIDIA driver (577+) and the CUDA 12.8 toolkit at
`/usr/local/cuda`, plus Zig 0.17.1:

```bash
zig build -Doptimize=ReleaseFast -Dprefill-batch=1024

./zig-out/bin/squid5090 serve /opt/models/inkling-2-mini \
  --host 0.0.0.0 --port 8000 --mode nvfp4 --mtp 7
```

Leave `--ctx` and `--kv` unset on the first run and read the `[vram]` lines for what was fitted.
Keep the model directory on the WSL ext4 disk (not `/mnt/c`): the loader reads 20.2 GB of
safetensors and 9P reads from Windows drives are several times slower.

The checkpoint is 20.2 GB on disk (19.53 GB main + 0.64 GB MTP), and the WSL virtual disk grows
on its host drive, so that drive needs the space free.
